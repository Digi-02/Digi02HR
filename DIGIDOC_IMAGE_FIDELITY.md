# DigiDoc image export fidelity

This table describes the export foundation after Step 1A. Layout attributes are validated and old image nodes default to `layout: inline`; the editor does not expose those layout choices yet. The four non-inline layouts are planned for later steps.

| Format | In line with text | Wrap text | Break text | Behind text | In front of text |
| --- | --- | --- | --- | --- | --- |
| PDF | **Approximate.** ReportLab embeds the image and honors size, alignment, crop, and spacing. Images inside paragraphs are emitted as separate flowables, so text does not continue beside them. | **Not supported (planned).** Falls back to ordinary image flow; no text wrapping. | **Not supported (planned).** Falls back to ordinary image flow; explicit mode is not yet applied. | **Not supported (planned).** Falls back to ordinary image flow; no canvas overlay. | **Not supported (planned).** Falls back to ordinary image flow; no canvas overlay. |
| DOCX | **Exact.** Image bytes are embedded as an inline DrawingML picture with alt text, width, alignment, crop, and paragraph spacing. | **Not supported (planned).** Export currently places the image inline. | **Not supported (planned).** Export currently places the image inline. | **Not supported (planned).** Export currently places the image inline. | **Not supported (planned).** Export currently places the image inline. |
| ODT | **Exact.** Image bytes are embedded in a `draw:frame` anchored as a character with width, alignment, crop, alt text, and paragraph spacing. | **Not supported (planned).** Export currently places the image inline. | **Not supported (planned).** Export currently places the image inline. | **Not supported (planned).** Export currently places the image inline. | **Not supported (planned).** Export currently places the image inline. |
| RTF | **Approximate.** The image is embedded with `\\pict` and PNG/JPEG data, with dimensions, alignment, and spacing; application-specific layout can vary. | **Not supported (planned).** Export currently places the image inline. | **Not supported (planned).** Export currently places the image inline. | **Not supported (planned).** Export currently places the image inline. | **Not supported (planned).** Export currently places the image inline. |
| TXT | **Not supported.** Replaced with `[Image: alt text]` on its own line; spacing becomes up to five blank lines. | **Not supported (planned).** Same text marker fallback. | **Not supported (planned).** Same text marker fallback. | **Not supported (planned).** Same text marker fallback. | **Not supported (planned).** Same text marker fallback. |

For every binary format, an image is read only from an image asset belonging to the document's organization. Missing or inaccessible assets produce an explicit `[Image unavailable: alt text]` placeholder. They never cause an export to load a path or URL from document JSON.

ReportLab does not provide Word-style inline images that continue text on the same line. DigiDoc therefore represents inline PDF images as separate flowables; true wrap and positioned overlays require a custom canvas layout and remain planned. Text-only output cannot preserve image pixels or visual layout.
